# 技术选型与开发路线

建议用 **Cocos Creator 3.8 LTS + TypeScript** 做正式版。先用 H5 快速分享试玩，同时尽早跑一次微信小游戏真机预览。安卓 APK 和 TapTap 是后续发布选项。首轮验证采用 [首版玩法规则](10-首版玩法规则.md)，做一张图、一次战中进化和一场能打到结算的战斗。

## 引擎比较

| 选项 | 适合什么 | 本项目取舍 |
|---|---|---|
| Cocos Creator 3.8 LTS + TypeScript | 有 2D 场景、图集、动画和预制体，官方构建目标包含 H5、微信小游戏和安卓。 | 技术首选。能承接现有 JS 的战斗结构，也能在编辑器里装配各时代的战场与角色。 [Cocos 跨平台文档](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/) |
| 原生 Canvas + JavaScript | 保持现有原型，快速调整规则并在浏览器运行。 | 保留为参考。网页界面、绘制、资源与小游戏运行环境的差异需要自行适配。现有项目的 `game.js` 直接调用 DOM 和 Canvas。 [Cocos 微信小游戏运行环境说明](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-wechatgame.html) |
| LayaAir 3 | 同样支持 Web、微信小游戏和原生端，也适合本项目的二维玩法。 | 可作备选。现阶段没有依赖 LayaAir 的资产或团队工作流，先集中验证 Cocos 的真机路径。 [LayaAir 发布文档](https://www.layaair.com/3.x/doc/basics/) |
| Godot 4 | 适合桌面或原生移动端。官方网页导出走浏览器 WebAssembly 与 WebGL 2.0。 | 若发布目标改为以独立安装版为主，再评估。微信小游戏适配需要另行验证。 [Godot Web 导出文档](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_web.html) |
| 团结引擎 | 有官方微信小游戏构建和 SDK 路径，适合有 Unity/C# 经验的团队。 | 现有原型是 JavaScript，项目美术是二维精灵，暂按 TypeScript 路线减少切换成本。 [团结引擎微信小游戏手册](https://docs.unity.cn/cn/tuanjiemanual/Manual/WechatSDK.html) |

## 现有原型能用什么

`index.html` 和 `style.css` 提供网页外壳。`game.js` 负责 HUD、输入和浏览器循环，以每秒 30 步运行 `battle.js`。战斗模块独立维护单位、纵深、寻敌、波次、进化、工事和胜负。现有桌面版可在一局内经历石器、青铜和铁器，三种基本兵可直接招募，第四种需研究解锁。

`art.js` 绘制手绘地形与特效，`models.js` 通过 Three.js 加载 KayKit GLB 角色和骨骼动画。战斗时刻驱动动作，场景坐标决定脚下位置。迁移时可把 `battle.js` 移进 TypeScript，并在 Cocos 样场中验证导入一名近战、一名远程和这套 GLB 动作的效果。桌面版的浏览器试玩已可使用，微信小游戏仍需走真机验证。 [Three.js AnimationMixer](https://threejs.org/docs/pages/AnimationMixer.html) · [KayKit Adventurers](https://kaylousberg.itch.io/kaykit-adventurers)

## 战斗实现

- **战斗模拟**用固定时间步维护状态。出兵、升代、建塔、放技能都提交给同一份战斗状态。伤害、范围和目标资格由规则计算，屏幕动画读取结果。首版继续采用原型的固定步长思路，实际频率按手机压力测试调整。支持用同一组时间和输入重打战局，可以单独验证经济、克制和升代。
- **道路和镜头**采用 2D 平面。三条纵深带给近战阻挡、弓手后站、突袭沿边和长矛拦截使用，屏幕仍是一条有宽度的路。关卡记录单位沿路位置和所在纵深，渲染按脚底排序。敌方塔的可命中兵种由规则标签筛选，溅射沿用同一筛选。战场规则使用关卡坐标，屏幕比例变化只影响画面和界面。
- **内容配置**分为兵种、时代、塔、关卡和视觉资源。兵价、生命、伤害、进化时间、关键敌军时机、图集索引分别可调。先用有类型校验的配置，内容较多时再做表格导入。新战役可更换左右时代、地图和敌军配置，重用战斗模拟。
- **美术生产**按背景、地面、左右城门、士兵、音效和特效分开。士兵以脚底为共同锚点，做站立、行走、攻击、受击和倒地。占位阶段先让一个近战和一个远程动得清楚，再按模板扩兵种。用图集和复用节点处理同屏群战；具体内存和帧率看真机。 [Cocos 精灵组件](https://docs.cocos.com/creator/3.8/manual/en/ui-system/components/editor/sprite.html) · [动画编辑器](https://docs.cocos.com/creator/3.8/manual/zh/animation/edit-animation-clip.html)
- **存档与平台**首版做单机，保存在本机。存档包含版本、通关记录、金币、已解锁内容和设置。在结算后保存，战中完整续游戏可在测试确有需要后做。读取、保存和平台服务单独接入。素材随战役增长后用资源包按需加载，首场需要的图和声音一起放。 [Cocos 资源包](https://docs.cocos.com/creator/3.8/manual/zh/asset/bundle.html)

## 开发和验证顺序

1. **最小跨端样场。** 用一个横屏场景放进左右基地、道路、一个小兵和触屏按钮。导出 H5 和微信小游戏，在手机上确认启动、触摸、横屏安全区、音频、前后台暂停恢复和本地存档。iPhone 与安卓至少各看一次；若没有正式 AppID，先用文档支持的测试方式，后续用项目 AppID 做真机预览。 [Cocos 微信小游戏构建选项](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-wechatgame.html) · [Cocos SafeArea 组件](https://docs.cocos.com/creator/3.8/manual/zh/ui-system/components/editor/safearea.html)
2. **一场可从头打到尾的战斗。** 做石器升青铜、三种基本兵加一个可解锁专用兵、一座只打前排的投石台、一个可施放技能。敌人分阶段换阵，让玩家遇到正面压线、侧绕和重盾三种问题。能在同一局看到老兵护新兵、塔与远程的分工。先用配置调实际节奏，再决定成品时长。
3. **完成一场正式战役。** 补上铁器攻城阶段和第二次进化。用 H5 发给少量试玩者，微信真机跑兵群峰值和长局，观察画面、输入和内存；改预算、节点数量和资源加载以实测为准。之后再扩战役、装备和遗物。

## 发布顺序

H5 适合先分享玩法。微信小游戏是主要的手机验证渠道，Cocos 可以导出对应包体，要单独处理渠道的账号与发布流程。安卓包可用于后续独立测试和 TapTap APK 分发。TapTap 的即点即玩有另一条官方转换路径，Cocos 3.8.x 可用其适配插件。先选择一个渠道正式制作，等第一场战役的玩法稳定后再准备第二个渠道。 [Cocos 微信发布](https://docs.cocos.com/creator/3.8/manual/zh/editor/publish/publish-wechatgame.html) · [TapTap 安卓发布](https://developer.taptap.io/docs/zh-Hans/store/store-creategame/) · [TapTap 小游戏适配](https://developer.taptap.cn/minigameapidoc/dev/engine/Cocos-Laya-Egret/)

目前验证的是文档中的导出路径与本地原型结构。Cocos 项目、包体、真机性能与渠道审核都要在进入开发后验证。
